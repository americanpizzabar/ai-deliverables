# 有機EL照明機器 新規開発プロジェクト 初期要件定義書（プロトタイプWebアプリ開発）

## 1. プロジェクト概要

本プロジェクトは、調査部からのマーケティング調査書（MKTG-REP-20240729-OLED）に基づき、高成長が予測される有機EL（OLED）照明機器の新規開発要望に応えるための初期フェーズとして、**「OLED照明の魅力を効果的に訴求し、潜在顧客の具体的な要望をヒアリング・可視化するためのプロトタイプWebアプリケーション」**の開発を目的とします。

ECUANEST合同会社は、OLEDの薄型・軽量、面発光、高演色性、フレキシブル性といった独自特性を最大限に活かしたデザイン統合力、ソリューション提供、カスタマイズ性を強みとし、特定の顧客課題を解決する革新的な照明ソリューションを提供することを目指します。

本プロトタイプWebアプリケーションは、市場ニーズの検証、顧客エンゲージメントの向上、および事業化可能性の評価を迅速に進めるためのツールとして機能します。物理的なOLED照明機器の設計・製造は、このプロトタイプを通じて得られた顧客フィードバックと市場評価に基づき、次フェーズで検討します。

## 2. 市場と機会

有機EL照明市場は、2023年の約3億ドルから2030年には約25億ドルに達すると予測されており、年平均成長率（CAGR）35%を超える高成長市場です。特に、デザイン照明、車載照明、医療・美容分野、スマートホーム向けが主要な成長ドライバーとなっています。（参照：MKTG-REP-20240729-OLED）

**主要な機会:**
*   **高付加価値市場への参入**: 高演色性、均一な光質、フレキシブル性、透明性といったOLED独自の特性を活かし、デザイン性や機能性を重視する高価格帯市場を狙う。
*   **IoT連携によるスマート照明ソリューション**: 調光・調色、人感センサー、生体リズムに合わせた照明など、IoT技術との連携による新たな価値創造。
*   **カスタマイズ需要の取り込み**: 建築家やデザイナー、特定のBtoB顧客のニーズに応じた柔軟なカスタマイズ対応。
*   **サステナビリティへの貢献**: 省エネ・長寿命、環境負荷の低い製造プロセスによるブランド価値向上。

## 3. ターゲット顧客（プロトタイプWebアプリのユーザー）

初期ターゲットとして、OLED照明の特性を最大限に評価し、投資を惜しまない以下のペルソナを設定します。プロトタイプWebアプリケーションは、これらの顧客層からの情報収集を目的とします。

*   **BtoC - 富裕層住宅オーナー / デザイナーズマンション居住者**:
    *   **ニーズ**: 空間デザインへのこだわり、最新技術への関心、快適性・健康志向、パーソナライズされた照明体験。
    *   **Webアプリでの提供価値**: 居住空間の質を高める美的で機能的な照明の提案、フレキシブルなデザインの視覚化、目に優しい光質の情報提供、スマートホーム連携の可能性提示。
*   **BtoB - 建築家 / インテリアデザイナー / ホテル・商業施設開発担当者**:
    *   **ニーズ**: プロジェクトの差別化、デザインの自由度、高機能性、省エネ、長期的なメンテナンスコスト削減、顧客への新たな体験提供。
    *   **Webアプリでの提供価値**: 建築や空間デザインに合わせたカスタマイズ可能な照明ソリューションの提示、高演色性による商品価値向上事例の紹介、IoT連携による運用効率化のデモンストレーション。

## 4. 競合分析と差別化戦略

主要競合はLG Display、Konica Minolta、OSRAM (ams OSRAM)、Verbatimなどであり、主にパネル供給や特定のニッチ市場に特化しています。ECUANEST合同会社は、以下の点での差別化を図ります。

*   **デザイン統合力とソリューション提供**: 単なるOLEDパネルの提供に留まらず、OLEDの特性を活かしたデザインコンサルティングから、具体的な照明ソリューションの企画・開発までを一貫して提供。
*   **高度なカスタマイズ性**: 顧客の具体的な要望（サイズ、形状、色温度、輝度、フレキシブル性、透明性など）に応じた柔軟なカスタマイズ対応能力。
*   **IoT連携とスマート機能の強化**: 単体照明に留まらず、スマートホーム・スマートビルディングシステムとのシームレスな連携による付加価値創造。
*   **ブランドストーリーとサステナビリティ**: 環境負荷の低い製造プロセスや長寿命設計によるサステナブルなブランドイメージの確立。

## 5. プロトタイプWebアプリケーションの目的とスコープ

### 5.1. 目的

*   OLED照明の先進性と魅力を潜在顧客に効果的に伝え、興味喚起を図る。
*   顧客がOLED照明に求める具体的な機能、デザイン、用途、予算感などをヒアリングし、今後の製品開発の方向性を定めるための情報収集を行う。
*   OLED照明のカスタマイズ可能性を視覚的に提示し、顧客の想像力を刺激する。
*   事業化可能性を評価するための初期的な市場反応と顧客フィードバックを得る。

### 5.2. スコープ

本プロジェクトのスコープは、**「OLED照明に関する情報提供、カスタマイズシミュレーション（簡易版）、および顧客要望ヒアリングフォームを核としたプロトタイプWebアプリケーションの開発とデプロイ」**に限定されます。物理的なOLED照明機器の製造、販売、設置は次フェーズ以降の検討とします。

## 6. 機能要件 (Functional Requirements)

### 6.1. 製品情報表示機能
*   **FR-001: OLED照明の概要ページ**: OLED照明の基本特性（薄型、面発光、高演色性、フレキシブル性、低発熱など）を分かりやすく説明する。
*   **FR-002: 想定製品ラインナップ紹介ページ**: 想定されるOLED照明製品のカテゴリ（例: デザイン照明、タスク照明、フレキシブル照明）と、それぞれの特徴、適用例を画像や動画で紹介する。
*   **FR-003: 技術詳細ページ**: 高演色性のメリット、IoT連携の可能性、環境性能など、より技術的な側面を解説する。

### 6.2. カスタマイズシミュレーション機能（簡易版）
*   **FR-004: 基本形状・サイズ選択**: OLEDパネルの基本形状（例: 四角、丸、細長）と、いくつかのプリセットサイズを選択できる。
*   **FR-005: 色温度・明るさ調整**: スライダーなどで色温度（暖色〜寒色）と明るさ（輝度）を調整し、その変化をイメージ画像で確認できる。
*   **FR-006: フレキシブル性デモンストレーション**: 曲げられるOLEDの特性を、簡易的なアニメーションや画像で表現する。
*   **FR-007: ユースケース適用イメージ**: 選択したカスタマイズが、特定の空間（例: リビング、オフィス、ホテルロビー）にどのように適用されるかのイメージ画像を複数パターン表示する。

### 6.3. 顧客要望ヒアリング・問い合わせ機能
*   **FR-008: 問い合わせフォーム**: 氏名、会社名、連絡先、具体的な要望（自由記述）、想定用途、予算感、希望納期などを入力できるフォームを提供する。
*   **FR-009: ファイル添付機能**: 顧客が参考資料（例: 空間デザイン図面、イメージ画像）を添付できる機能（オプション、簡易プロトタイプではURL指定でも可）。
*   **FR-010: フォーム送信後の確認・完了通知**: フォーム送信後に確認メッセージを表示し、同時に自動返信メール（簡易版）を送信する。

### 6.4. 管理機能（簡易版）
*   **FR-011: 問い合わせ内容一覧表示**: 管理者向けに、受信した問い合わせ内容を一覧で表示する簡易的な機能（認証付き）。
*   **FR-012: 問い合わせ詳細表示**: 個別の問い合わせ内容の詳細を確認できる。

## 7. 非機能要件 (Non-Functional Requirements)

### 7.1. 性能
*   **NFR-001: レスポンス速度**: 各ページの表示は3秒以内、フォーム送信は5秒以内とする。
*   **NFR-002: 同時アクセス数**: 最大100ユーザーの同時アクセスに耐えうる設計とする（プロトタイプとして）。

### 7.2. 可用性
*   **NFR-003: 稼働時間**: 24時間365日稼働を目標とする。
*   **NFR-004: バックアップ**: 問い合わせデータは日次でバックアップを取得する。

### 7.3. セキュリティ
*   **NFR-005: データ保護**: 顧客の個人情報は暗号化して保存し、HTTPS通信を必須とする。
*   **NFR-006: アクセス制御**: 管理機能にはパスワード認証を導入する。

### 7.4. 保守性・拡張性
*   **NFR-007: コード品質**: 可読性の高いコード、適切なコメント、TypeScriptによる型安全性を確保する。
*   **NFR-008: ドキュメント**: API仕様、コンポーネント構成、デプロイ手順などをドキュメント化する。
*   **NFR-009: 拡張性**: 将来的な機能追加（例: ログイン機能、ユーザーダッシュボード、高度なシミュレーション）を考慮したアーキテクチャとする。

### 7.5. ユーザビリティ
*   **NFR-010: 直感的なUI/UX**: ユーザーが迷わず情報にアクセスし、フォームを操作できるよう、シンプルで分かりやすいデザインとする。
*   **NFR-011: モバイル対応**: スマートフォン、タブレット、PCの各デバイスで適切に表示・操作できるレスポンシブデザインとする。

### 7.6. 環境
*   **NFR-012: ブラウザ互換性**: 主要なモダンブラウザ（Chrome, Firefox, Safari, Edgeの最新2バージョン）に対応する。

## 8. システム構成と技術スタック

### 8.1. システムアーキテクチャ
*   **フロントエンド**: Next.js (React) によるSPA (Single Page Application) またはSSR/SSG。
*   **バックエンド**: Next.js API Routes (Node.js) を利用した簡易API。
*   **データベース**: 問い合わせデータの一時保存には、簡易なKVストア（例: Vercel KV）またはNoSQLデータベース（例: Firebase Firestore）を検討。
*   **デプロイ環境**: Vercelによる自動デプロイとホスティング。

### 8.2. 技術スタック
*   **フレームワーク**: Next.js (App Router)
*   **言語**: TypeScript
*   **UIライブラリ/CSSフレームワーク**: React, Tailwind CSS
*   **フォームライブラリ**: React Hook Form (バリデーション、状態管理)
*   **データストア**: Vercel KV (Redis) または Supabase (PostgreSQL) ※簡易プロトタイプのため、選択肢は柔軟に
*   **バージョン管理**: GitHub
*   **デプロイ**: Vercel
